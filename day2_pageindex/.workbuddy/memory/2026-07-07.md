## 检索修复 — 匹配度永远是最第一篇文档（snippets 截断偏差）
- 根因: `_locate_with_llm` 中 `snippets[:MAX_SNIPPETS]`（MAX_SNIPPETS=300）只取前 300 个片段，但这些片段是按文档顺序排列的，而第一篇文档（如 DLT 5582 有 5776 行、大量节点）占光了前 300 个位置，导致第 2-7 篇文档的片段完全不进入 LLM 视野
- 修复: 改为轮询均匀抽取 — 将 snippets 按文档分组，然后从每个文档轮流取一个片段，确保每篇文档都有公平的片段数进入 LLM prompt
- 效果: 7 篇文档，每篇约分到 42 个片段，LLM 能看到所有文档的结构概览，不会只定位第一本
- 变更文件: `backend/server.py`（`_locate_with_llm` 方法）

## 检索修复 — 检索表里有但搜索不到（内容在深层节点）
- 用户问题: "3500米海拔下，10kV架空线路，悬式绝缘子需要几片"
- 现象: 结构片段中存在"7 绝缘配合、防雷和接地"节点（含 7.0.3 海拔3500m、2片绝缘子），但 AI 回答"没有任何关于绝缘子选型...的规定"
- 根因分析:
  1. `MAX_STRUCTURE_PREVIEW = 200` 太短，包含多条文的父节点 text_preview 只能显示到 7.0.1/7.0.2，LLM 看不到 7.0.3 的关键内容
  2. `MAX_SNIPPETS = 300` 只够每篇文档 42 个片段，大文档后面的章节节点在轮询中排不到
  3. `_collect_snippets` 不排序，子节点按遍历顺序排列，大节点（含多条文）没有优先展示
  4. `_extract_details` 不提取 query 中的数字关键词（如"3500"），无法通过数字匹配找到 7.0.3
- 修复:
  - `MAX_STRUCTURE_PREVIEW` 从 200 增加到 400
  - `MAX_SNIPPETS` 从 300 增加到 500
  - `_collect_snippets`: 按节点信息量（text 长度 + 子节点数 × 100）降序排列，大节点优先进入 LLM prompt；text_preview 被截断时追加子节点标题（如 `[含子节点] 7.0.1 · 7.0.2 · 7.0.3`），让 LLM 知道父节点包含哪些子条文
  - `_extract_details`: 增加数字关键词提取（`\b\d{2,4}\b`），匹配 title 和 text 中是否包含 query 中的具体数值（如"3500""10""110"）
- 变更文件: `backend/server.py`（`_collect_snippets`, `_locate_with_llm`, `_extract_details`）
