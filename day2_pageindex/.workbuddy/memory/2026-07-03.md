## 2026-07-06 RAG 检索深层节点失败 — 诊断与修复

### 用户反馈
查询"导线舞动的电气间隙该如何计算"时，LLM 答复"无法给出计算方法"，而文档 8.0.6 节点包含相关内容。

### 根因链
1. get_document_structure() 去掉 text 字段 — retrieve.py remove_fields(structure, fields=['text'])
2. 深层节点被截断 — flat[:30] 只取前 30 节点，8.0.6 是第 67 个
3. 章节号正则 \b 在中文不匹配 — Python \b 在汉字(\w)与数字(\w)间无 boundary
4. 上下文预算被低相关性节点占满 — 含 \d+\.\d+ 标题的节点 n-gram 匹配到通用词

### 修复
- _raw_structures 缓存：reload 时存完整 JSON（含 text），绕过 get_document_structure
- 两遍收集+评分排序：title命中×10 + text[:500] n-gram命中数，优先生取完整 text
- 章节号正则：\b → (?:^|[^\w.])(\d+(?:\.\d+))(?=[^\w.]|$)
- 中文 n-gram 滑动窗口：2/3/4 字窗口，过滤纯停用字

### 验证
- "导线舞动的电气间隙该如何计算"：8.0.6 排名第 1（1501 字完整条文）
- 共提取 8 个章节，答案 1499 字，正确引用 8.0.6 内容

## 2026-07-06 公式渲染修复

### 问题
LLM 返回的公式使用 `\tag{}` 命令（如 `\tag{6.2.3-1}`），KaTeX 不支持 `\tag`，导致整个公式渲染为纯文本乱码。

### 修复
1. **MarkdownView.tsx** — `rehypeKatex` 配置 `{ throwOnError: false }`，KaTeX 解析失败时降级显示而非报错
2. **backend/server.py** — done 事件前 `re.sub(r'\tag\{[^}]*\}', '', full_answer)` 清理 `\tag{}` 命令
3. **_build_final_prompt** — prompt 新增"公式中不要使用 \tag 命令标记编号"指令，从源头减少问题
